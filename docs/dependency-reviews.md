## 2026-10-07 (app lock, machine icon, one-step alert setup): no coordinate added

Written before the code, as the rule asks. Why a library was considered: the app lock needs the phone's fingerprint, face or PIN prompt, and `androidx.biometric` is the usual wrapper. It is **not adopted**: Android 11 and later (API 30) has `android.hardware.biometrics.BiometricPrompt` with `setAllowedAuthenticators(BIOMETRIC_WEAK | DEVICE_CREDENTIAL)` in the platform, and Android 8 to 10 has `KeyguardManager.createConfirmDeviceCredentialIntent`, so the app needs no extra code from outside the repository for either (`DeviceAuth.kt`). The wrapper's only gain is one prompt with a fingerprint on Android 8 to 10; the cost is a new library in the signing path of an app that holds an SSH key, and its own dependencies (`androidx.fragment`, `androidx.core`), which Paddock does not otherwise carry. Nothing else in this change needs one: the OS icon is a `uname -s` over the existing SSH port and three vector paths; the alert setup is a POSIX `sh` script piped over SSH stdin and the already pinned relay (the relay script itself is unchanged, so `host/SOURCE.json` and its hash are untouched); the ntfy app is reached by an Android intent and a `<queries>` package entry, not a library.

`gradle/libs.versions.toml`, `app/gradle.lockfile` and `core/gradle.lockfile` are unchanged by this work, so there is no Socket row to write. A library that would have to enter later (for example `androidx.biometric` if a fingerprint-first prompt on Android 8 to 10 is wanted) needs its row here first.
