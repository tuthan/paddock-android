## Why sshlib

1. It is the only candidate that meets S1 to S6 as written, including the 15 s keepalive and 30 s detection requirement.
2. The Keystore signing hook is part of its public API; sshj needed signer-level replacement and a security-provider swap, which is the kind of code that breaks on a library update.
3. sshj as published fails the dependency review (critical CVE through BouncyCastle 1.84). It was usable only through a version override of a crypto library, which the review had to approve as an exception.
4. 77 kB against 414 kB after R8.

The smaller graph belongs to sshj (8 components against 14); that is the cost accepted. The extra components are `tink`, `jbcrypt`, `simplesocks`, `asia.hombre:kyber` with `keccak`, and the `kotlincrypto` error and random libraries.

## Requirements the production adapter inherits

- **Cipher list.** API 26 and 27 have no ChaCha20 provider and sshlib offers `chacha20-poly1305@openssh.com` whenever the server does; key exchange then fails after the host key is verified. Restrict to `aes256-gcm@openssh.com`, `aes128-gcm@openssh.com`, `aes256-ctr`, `aes128-ctr` (both directions).
- **Signing.** `Signature.getInstance("SHA256withECDSA")` with no provider name; naming `AndroidKeyStore` fails on API 26 for both libraries. The proxy returns `string("ecdsa-sha2-nistp256") || string(mpint r || mpint s)`, converted from the DER signature.
- **Keepalive.** Adapter-owned: ping on a dedicated thread every 15 s with a 10 s reply timeout; treat a timeout as link down. `Connection.ping()` holds the connection monitor while it waits.
- **Closing.** Because `ping()` can hold the monitor on a stalled link, `close()` blocks; close from a daemon thread and do not wait for it.
- **Exit status.** After reading the streams, wait for `EXIT_STATUS or CLOSED`, not EOF: EOF can arrive before the status and yields a null exit.
- **Host key.** Verify inside `connect(ServerHostKeyVerifier, …)`; it runs before any authentication.
- **R8.** The minified build passed S1 to S6 with only the adapter kept and `-dontwarn **`; the production rules must keep what the adapter reaches and be re-tested under R8.

## Adapter rules added after the 2026-10-01 review

- **Cancellation.** sshlib's reads, writes and waits block their thread and do not return on interrupt, and `withContext(Dispatchers.IO) { blocking }` (or `flowOn`) makes a cancelled caller wait for that thread. So no coroutine waits on sshlib directly: a stream's stdout and stderr are each read on a worker thread into a bounded channel (16 chunks) that the flow drains; writes, `closeStdin` and channel opens run on a worker behind a deferred; `awaitExit` polls every 200 ms. A cancelled collector returns at once (0 to 1 ms measured on API 26 and 37), `withTimeout(1 s)` around the first line of a silent stream fires at 1000 ms, and `StreamChannel.close()` releases the slot immediately and closes the sshlib session off-thread, which ends the reader. The port's KDoc makes prompt cancellation and resource release on `close()` a requirement for every implementation.
- **Channel slots.** Eight per session, under OpenSSH's `MaxSessions` default of ten. Waiting for a slot is bounded (30 s by default) and fails with `ChannelsBusy` instead of hanging.
- **Exec deadline.** `ExecLimits.deadline` starts once a slot is held and covers opening the channel as well as running the command. A session that opens after the deadline (or after the caller was cancelled) is closed the moment it opens and its command is never sent. **Limit:** closing a channel does not stop the remote process. There is no pty, so sshd sends no SIGHUP, and sshlib has no `signal` channel request. A command that neither reads stdin nor writes output (`sleep 30` past a 2 s deadline) runs on the host until it exits by itself, and sshd keeps its session counted against `MaxSessions` until then. A command that reads stdin or writes output ends at its next read or write, because sshd closes its pipes. Paddock only issues short herdr calls and relay streams, and the relay exits within 2 s of stdin EOF, which closing its channel causes, so nothing is left running for long; the test that checks this is named for what it proves (`aCommandPastItsDeadlineFailsOnTimeAndTheSessionSurvives`), not "killed".
- **First trust.** sshlib calls the host-key verifier on its receive thread, inside the synchronized key-exchange handler and before it has checked the server's signature over the exchange. So the verifier only records the user's "trust"; the pin is written after `Connection.connect` returns (key exchange complete) and before authentication, and is kept if authentication then fails (the phone is often not authorized yet on first contact). sshlib's key-exchange timer keeps running while the verifier waits, but it can only close the socket: the waiting connect is woken by the receive thread, which is the one blocked in the verifier. The question therefore has its own deadline, 180 s on first contact, after which it is withdrawn and the attempt fails as a timeout; sshlib's timer is set 10 s beyond it so an answer given in time still finds the socket open. sshd's `LoginGraceTime` (120 s by default) can end the pre-auth connection first; that attempt then fails and the next one asks again. A pinned host keeps the 10 s timers.
- **Withdrawing a question.** The verifier runs the question as a child of the connect coroutine (`askFromCallbackThread`), so cancelling the connect (the app went to the background) withdraws the dialog at once and releases sshlib's thread; the connect itself returns at once because sshlib's blocking calls run on their own thread. Every question has an id and the dialog answers by id, so a tap on a withdrawn dialog answers nothing.
- **Failures that are not the network.** Every non-cancellation throwable from authentication closes the connection (a Keystore `InvalidKeyException` or `ProviderException` from the signing proxy escapes sshlib raw). A Keystore or signing failure is `KeyUnavailable`; sshlib wraps every I/O error during publickey authentication as "Publickey authentication failed." while a key the server rejects returns false, so an exception is classified by its cause, not by that message. A missing phone key (app data lost), an imported key whose wrapped copy cannot be read, and an unreadable pin store are `KeyUnavailable` or `HostKeysUnreadable`: the connection owner stops and waits for the user instead of retrying, and the host screen says what to do.
- **Portable quoting.** sshd runs the command line with the account's login shell (`$SHELL -c`), not `sh`, so `argvToCommand` must produce a line that means the same under sh, bash, dash, zsh, fish and tcsh. A bare word is only `[A-Za-z0-9_./-]` (zsh expands an unquoted `=word`; `:`, `@`, `%`, `+`, `,` and `=` used to be bare and are now quoted). Everything else is single-quoted, and an argument containing `'` or `\` is rejected along with NUL, CR and LF: inside single quotes fish reads `\'` and `\\` as escapes, and no way of embedding a quote works in every shell. None of the app's constant scripts (`RelayInstaller`, `HostSessionController`) contains either character; a host path that does (a `$HOME` or socket path with a quote or backslash) is refused with an `IllegalArgumentException` rather than sent. Checked through `/bin/sh` and bash on the development host (dash, zsh, fish and tcsh are exercised by `PosixTest` wherever they are installed) and through the test account's real login shell from API 26 and 37. A `!` is quoted, not rejected, on the understanding that tcsh applies history substitution to interactive input only; tcsh is not installed on the development host, so that is unverified (no argument the app builds contains `!`). sshlib encodes the exec command as ISO-8859-1, so the adapter hands it the UTF-8 bytes as Latin-1 characters; non-ASCII arguments then reach the host unchanged.
- **Algorithms.** Ciphers as above. Key exchange: `curve25519-sha256` (and its libssh alias), `ecdh-sha2-nistp256/384/521`, `diffie-hellman-group18-sha512`, `-group16-sha512`, `-group-exchange-sha256` (group size at least 2048 bits, preferred 3072) and `-group14-sha256`; no SHA-1 exchange (`group1-sha1`, `group14-sha1`, `group-exchange-sha1`). sshlib appends `ext-info-c` and the strict-KEX marker (`kex-strict-c-v00@openssh.com`) itself. MACs, used only with the CTR ciphers: `hmac-sha2-256-etm`, `hmac-sha2-512-etm`, `hmac-sha2-256`, `hmac-sha2-512`; no SHA-1 MAC (sshlib has no MD5 MAC). Server host keys: on first contact only `ssh-ed25519`, `ecdsa-sha2-nistp256/384/521`, `rsa-sha2-512`, `rsa-sha2-256` (no `ssh-rsa` SHA-1 signatures, no `ssh-dss`); once a host is pinned, only the pinned key's type is offered, so a server that adds a key of another type still presents the pinned one instead of reading as Changed. sshlib hands the verifier the negotiated signature name, so an RSA key is pinned as `rsa-sha2-512` or `rsa-sha2-256` while its blob says `ssh-rsa`; pins are compared by key type (all three RSA names are one type) and blob, and an RSA pin is offered both SHA-2 signatures. A pin of a retired type (`ssh-dss`) gets the modern offer and the host then reads as Changed. A server that only speaks SHA-1 algorithms can no longer be reached; OpenSSH has supported all of the above since 7.x. Measured against OpenSSH 10.5p1 on API 26 and 37: `curve25519-sha256`, `aes256-gcm@openssh.com`, and with a second throwaway sshd holding Ed25519, ECDSA and RSA host keys, an ECDSA pin negotiates `ecdsa-sha2-nistp256` and both RSA pin spellings negotiate `rsa-sha2-512` (Pinned, no question). If the kyber exclusion is reverted, `mlkem768x25519-sha256` must be added at the head of the key-exchange list.
- **Local-network gate.** Android 17 enforces the grant on the address a socket goes to, so the gate decides from the resolved address: a plain name is looked up (on its own thread, at most 3 s, only where the grant is enforced) and counts as local when any address is local; a failed lookup counts as not local. Literals and `.local` names are still decided without DNS. A connect that times out before the server answers, where the grant is enforced and missing, is reported as `LocalNetworkTimeout`, and the host screen offers the settings page.
- **Imported key in memory.** The connector wipes the PEM `CharArray` as soon as the key pair is built; the app loads a fresh copy for every attempt, so reconnects are unaffected. The passphrase is a `String` and cannot be wiped, and the decoded key pair lives until authentication returns.

## Kyber exclusion (2026-10-01)

Condition from the production approval: try excluding `asia.hombre:kyber`, `keccak` and `org.kotlincrypto` under R8, then `tink`, against the transport suite. Run with `-PminifiedTest=true` (the debug variant through R8 with the production rules plus `proguard-test.pro`), API 26 and API 36, against the throwaway loopback OpenSSH 10.5.

| Configuration | Result |
| --- | --- |
| kyber present | 19 of 19; negotiated `mlkem768x25519-sha256`, `aes256-gcm@openssh.com`, host key `ssh-ed25519` |
| kyber, keccak, kotlincrypto excluded | 20 of 20 (with the new negotiation test); negotiated `curve25519-sha256`, same cipher and host key. sshlib falls back by itself when the ML-KEM classes are absent; no KEX list needs to be set |
| also `tink` excluded | Fails: `NoClassDefFoundError com.google.crypto.tink.subtle.X25519`. `tink` stays |

**Shipped: the exclusion.** Three libraries (`kyber`, `keccak`, and the two `kotlincrypto` artifacts, each with its `-jvm` variant) leave the release runtime graph; sshlib's subtree is then `tink`, `jbcrypt` and `simplesocks`. **What it costs:** the post-quantum hybrid `mlkem768x25519-sha256`, which OpenSSH 10 prefers by default, is no longer negotiated; sessions use `curve25519-sha256`. Traffic captured today could be decrypted later by an attacker with a quantum computer. For this app that traffic is herdr control data and agent prompts over a LAN or VPN, so the exposure is accepted, but it is a real downgrade rather than a free simplification. To revert, delete the three `exclude` lines in `app/build.gradle.kts`, drop the `-dontwarn asia.hombre.kyber.**` rule, regenerate the locks, and the negotiation test must then be relaxed to accept `mlkem768x25519-sha256`.

**R8 (production rules, `app/proguard-rules.pro`).** sshlib loads ciphers, digests, key exchanges and signature classes by name, so `com.trilead.ssh2.crypto.{cipher,digest,dh}` and `signature` are kept; without that the minified build fails at key exchange (`ClassNotFoundException AesGcm$AES256`). The rest of the library shrinks normally. `-dontwarn` covers the deliberately absent kyber classes and annotation-only classes.
